# 0001. 모노레포 구조 채택

- 날짜: 2026-08-03
- 상태: 채택됨

## 배경

TaskTriage는 세 개의 독립 서비스(Spring Boot 백엔드, FastAPI 분류 서비스, React 프론트엔드)로 구성된다. 이를 각각 별도 git 저장소로 둘지, 하나의 저장소로 묶을지 결정이 필요했다.

## 결정

하나의 git 저장소 안에 `backend/`, `triage-service/`, `frontend/`, `docs/`로 나누는 모노레포 구조를 채택한다.

## 이유

- 개발자가 1인이라 여러 저장소를 오가며 컨텍스트 전환할 필요가 없다.
- 세 서비스에 걸친 변경(예: API 스펙 변경 → 백엔드+프론트 동시 수정)을 PR 하나로 리뷰할 수 있다.
- GitHub Actions에서 경로 기준(`paths:`)으로 서비스별 워크플로우를 분리할 수 있어 CI 이점을 그대로 가져갈 수 있다.

## 대안

- **서비스별 별도 저장소**: 실무에 더 가깝지만, 1인 포트폴리오 프로젝트 규모에서는 저장소 전환 비용이 이점보다 크다고 판단해 채택하지 않음.
